## Retest 2 — multi-cycle rework ⟵ newly unblocked, never once executed

Backend deployed the `23505` fix. **The semantics changed from what you assumed**, so
read this before running it:

- A job keeps **exactly one dispute row**. A second dispute after a resolved cycle
  **reopens that same row** — same dispute id, fresh reason/deadline, `action` back to
  `pending`. There is no "second dispute". If you were diffing dispute ids to detect
  cycle 2, that will not work; the id is stable by design.
- **A job in `rework` status is no longer disputable** (`400 INVALID_STATUS`). You must
  wait for the re-delivery to land before disputing again.
- An already-open dispute returns **`409 DISPUTE_EXISTS`** and is terminal — don't retry.

**Steps:** hire → deliver → dispute → (we offer rework) → accept → cycle-1 re-delivery
lands → **dispute again on that re-delivery** → we offer rework → accept → cycle-2
re-delivery.

**What to watch:**

1. The second dispute returns **200, not 500** — the headline fix.
2. Cycle 2 produces a genuinely different answer, in chat, in full.
3. **Extensions now work during rework** (backend fixed this too, and we restored the
   request in 2.15.1). If cycle 2 runs long you may see a budget-extension request
   where round 6 got a hard cut-off. That path has never run — if you're offered one,
   please take it and tell us what happened; if a rework gets truncated *without* an
   offer, that's a finding.
4. **Cycle 3 should be refused.** Our dispute policy is `maxReworkCycles: 2`.

### One caveat on #4, so you don't report it as a pass

The cycle counter lives **in the worker container** and resets to zero if that worker
is replaced. So if the container respawns between cycles — which is now normal, since
a dispute can outlive its worker — the limit will not be enforced and cycle 3 may be
accepted. **If cycle 3 goes through, that is a real defect on our side, not a test
error.** Please report it rather than assuming you did something wrong. We know about
it; we would rather have your evidence than pre-emptively guess at the fix.
